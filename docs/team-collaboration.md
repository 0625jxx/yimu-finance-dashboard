# 团队协作与版本控制说明

## 分支规范

- `main`：只保留通过全部测试、可直接提交的稳定版本。
- `develop`：日常集成分支。
- `feature/<topic>`：按功能建立短期分支，经评审后合并至 `develop`。
- 发布时由 `develop` 合并到 `main`，并创建带说明的版本标签。

## 提交规范

提交信息采用 `feat:`、`fix:`、`test:`、`docs:`、`chore:` 前缀。每次功能变化必须同时更新测试；合并前执行 `npm run validate`、`mvn test` 和浏览器回归。报告中的成员分工表记录课程提交材料采用的职责划分，实际提交作者与评审人应以远程仓库记录为准。

## 会议记录模板

每日站会记录日期、昨日完成、今日计划和阻塞问题。该模板仅定义协作流程，不虚构尚未提供的历史会议记录；如课程要求提交过程证据，应由小组补入真实会议纪要或远程仓库链接。
